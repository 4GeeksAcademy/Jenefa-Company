# Product Context: Automated Nightly Telemetry Script Orchestration

## 1. Business & Operational Background
HealthCore is an outpatient healthcare services company founded in 2011 in Austin, Texas, managing a cross-border network of 12 clinics across the United States (Texas, Florida, Georgia) and the United Kingdom (London, Manchester). The company serves a large patient base through approximately 200 staff members, bringing in an annual revenue of $28 million. 

Operationally, HealthCore's technology infrastructure is a fragmented patchwork of legacy platforms overseen by CTO James Osei's 6-person team. Because individual clinics handle their patient data using disjointed systems—ranging from two disconnected Electronic Health Record (EHR) systems to isolated billing engines and manual booking diaries—the company struggles to aggregate metrics across boundaries. This internal data fragmentation forces the CEO, Dr. Sandra Okonkwo, to make high-stakes operational choices using disconnected, slow weekly paper reports.

To break this administrative bottleneck, this script automation engine introduces an unattended background processing layer. It unifies cross-border operations monitoring by systematically parsing instrumented telemetry streams, calculating executive KPIs in real time, and recording structural timeline trends automatically.

## 2. Core Operational Architecture & Context
To shield critical public health services, protect corporate infrastructure, and maintain data pipeline reliability, the orchestration environment adheres to four strategic boundaries:

* **Strict Process Isolation:** The background routine runs as a separate process detached from the primary FastAPI application layer. It cannot block public API routes, consume request thread workers, or utilize web framework macros (`@repeat_every`, `lifespan` blocks, or `APScheduler`), ensuring web operations remain fully available to clinics.
* **Process-Driven Concurrency Locking:** The processing cell status inside the core data tier acts directly as an atomic distributed lock. This natively suppresses race conditions from overlapping cron jobs or accidental terminal fires without creating secondary artifacts, sidecars, or extra locking tables.
* **Archival Preservation Mapping:** Point-in-time telemetry records are dumped directly to standard CSV flat arrays inside the internal directory (`data/raw/`). This provides an immutable audit log backup for recovery and validation purposes.
* **Downstream ETL Separation:** The generated CSV archives serve strictly as data backups. The main internal data processing pipeline built by HealthCore Digital reads raw source records directly from the `telemetry_events` table using an optimized watermark logic. The core pipeline is never wired to ingest or read from these backup CSV files.

## 3. Compliance & Jurisdictional Protection
Operating across international borders means HealthCore falls simultaneously under two strict regulatory frameworks managed by Compliance Director Claire Whitfield: **HIPAA** in the United States and **UK GDPR** in the United Kingdom. 

Because data errors carry legal liabilities, this orchestration script must ensure all transactions, exceptions, and execution footprints are recorded with precision. Access controls, automated file creation, and execution error logs generated by the script are structured to form complete, immutable audit trails. This guarantees absolute compliance visibility if data governance controllers request audit records.
