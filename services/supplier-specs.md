# HealthCore Supplier & Vendor Directory API

## Overview & Objectives
This project establishes a unified single source of truth for HealthCore Digital to track internal procurement suppliers, vendor rates, and compliance statuses across our 12 cross-border clinical hubs. By replacing un-synchronized local spreadsheets with a structured FastAPI + TinyDB backend and an integrated backoffice frontend dashboard, we eliminate fragmented data pools while strictly enforcing international data safety baselines.

### Key Success Metrics
* **Idempotent Initial Seeding:** Installs baseline records via a dedicated CLI command, skipping duplicate entries if data is already present.
* **Failsafe Validation Rules:** Rejects out-of-bounds metrics or illegal status states instantly with an HTTP 422 code.
* **Granular Traceability:** Captures machine-generated updates under an explicit tracking field for data verification.
* **Real-time Interface Control:** Provides operational personnel a complete data management dashboard with real-time UI mutations and dynamic filters.

## Technical Stack
* **Framework:** FastAPI (Python 3.10+)
* **Environment & Run Tooling:** `uv` workflow manager
* **Database Engine:** TinyDB (JSON document store)
* **Data Validations:** Pydantic v2
* **Time Tracking Format:** ISO 8601 strings (`YYYY-MM-DDTHH:MM:SS`)

##  Data Architecture & Schemas

### Field Constraint Matrix
* **status:** Strictly bounded to either `"active"` or `"suspended"`. Checked via Enum or Pydantic field validator.
* **rate:** Must represent a positive number (`> 0.0`). Zero or negative inputs must be rejected before storage.
* **updated_at:** Automatically generated system timestamp. Never accepted via client write payloads.

### Pydantic Models

```python
from pydantic import BaseModel, Field
from typing import Optional

class SupplierBase(BaseModel):
    name: str = Field(..., min_length=1)
    product_category: str = Field(..., min_length=1)
    country: str = Field(..., pattern="^(US|UK)$")
    rate: float = Field(..., gt=0.0)
    status: str = Field(..., pattern="^(active|suspended)$")

class SupplierCreate(SupplierBase):
    pass

class SupplierUpdateStatus(BaseModel):
    status: str = Field(..., pattern="^(active|suspended)$")

class SupplierUpdateRate(BaseModel):
    rate: float = Field(..., gt=0.0)

class SupplierResponse(SupplierBase):
    id: int
    updated_at: str  # Generated by system in ISO 8601 format
```

##  Database Seeding Strategy
- Initial data population is handled by a standalone script rather than implicitly running inside application code blocks.

### Script Specifications
* **Filename:** `seed.py`
* **Execution Command:** `uv run seed`
* **Idempotency Protection:** The script must read `db.json` first. If data already exists, it must skip insertion to prevent creating duplicate rows.
* **Console Reporting:** Logs a final message to standard output indicating exactly how many new records were appended (e.g., `Inserted X records.`).

### Seed Data Content

## API Endpoints & Routing

### `POST /suppliers`
* Registers a new vendor in the directory.
* Validates properties and drops invalid inputs with an HTTP `422 Unprocessable Entity`.
* Returns the full created record, including its unique TinyDB-assigned integer `id`.

### `GET /suppliers`
* Fetches registered entries.
* Accepts optional query filters: `country` and `product_category`.
* Returns the complete un-filtered dataset if no query parameters are provided.

### `GET /suppliers/{id}`
* Resolves and returns a detailed matching model for a targeted item.
* Raises an HTTP `404 Not Found` response if the record integer index does not match any entry.

### `PATCH /suppliers/{id}/rate`
* Performs partial mutation on the `rate` property. Rejects values equal to or less than zero.
* Automatically refreshes the item's `updated_at` value to the current machine execution timestamp.

### `PATCH /suppliers/{id}/status`
* Mutates the operating visibility status of a targeted supplier.
* Accepts only the two string options defined in context: `"active"` or `"suspended"`.

### `DELETE /suppliers/{id}`
* Removes the target supplier record entirely from the directory.
* Raises an HTTP `404 Not Found` response if the integer identifier is missing from the database.

## Frontend Layout (`/uis/backoffice`)
A clean administration backoffice web layout must be mounted onto the server routing stack to facilitate quick updates for clinical operations staff.

### Interface & Functionality Requirements
* **Navigation Access:** Must provide an explicit, recognizable supplier directory page link from the standard application global menu.
* **Directory Grid:** Displays a dense table or list layout visualizing crucial columns: name, country, category, rate, and compliance status.
* **Seamless Dynamic Filtering:** Integrates reactive selection dropdown controls for both `country` and `category` to filter values immediately in-view without forcing a total browser page reload.
* **Onboarding Form:** Contains input forms that submit directly to the `POST /suppliers` pipeline. Must handle structural rejections by tracking validation codes and echoing clear visual error text if the payload drops out with a 422 code.
* **Instant Rate Overwrites:** Features quick numerical modification nodes that interact with the `PATCH /suppliers/{id}/rate` gateway, automatically forcing a view-model data sync once a server response confirmation completes.
* **Toggle Controls:** Includes interactive row-level buttons or detail toggles to switch compliance paths between `"active"` and `"suspended"`.
* **State Badging:** Uses explicit color-coded visual indicator badges (e.g., green for active, red/amber for suspended) to distinguish operational states instantly.
